## 原 5 项问题的修复状态（历史）

### 1. stdin 写满时取消不及时 — 已修复

原问题：向不读取 stdin 的程序写入 4 MiB，取消被阻塞的 stdin 写入拖住，程序仍可能完成并写文件。

修复：worker 用独立线程写子进程 stdin，以八个 32 KiB 帧的确认窗口限制缓冲；控制线程继续处理取消与心跳。IPC 取消不再排在 stdin 链后。五秒强制终止期限在发送取消帧之前启动，发送本身卡住也不会无限等待；重复取消等待同一清理结果。Modal 的后备清理使用固定 `modal@0.11.0` SDK 的 `closeStdin()`，绕过被堵住的 WritableStream；EOF 让该 worker 清理自己的进程组，不关闭共享 sandbox 或其他命令。此方法已核对下载的 SDK 声明与实现，并以真实 worker / SDK 边界夹具验证，未声称云端实测。

回归：`tests/integration/cancellation.test.mjs`、`tests/integration/cli-daemon.test.mjs`。另有 `tests/contract/modal-cancel.test.mjs`。覆盖不读 stdin 的取消和超时、卡住的传输发送、慢读者、并发 write 顺序、挂起 EOF、延迟文件副作用和 Modal 取消不影响同运行时中的其他任务。

### 2. stop / shutdown 后排队任务仍执行 — 已修复

原问题：停止仅取消 active 集合中的句柄，尚未进入执行的任务随后仍能启动。

修复：停止使已接受的项目请求失效，排队与准备中的任务在关键阶段检查执行代次。停止期间拒绝新执行；shutdown 关闭全局执行入口，并并行清理已有项目。stop 完成后仍允许用户主动重新执行，不永久禁用项目。dev 与前台同时运行时，先取消全部 active 句柄，再等待需要项目队列的 dev 清理。dev 句柄在等待 EOF 前即登记，EOF 挂起也能停止；启动被取消后仍回传已生成的源码。

回归：`tests/integration/coordinator.test.mjs`。覆盖运行中任务、排队前台与 dev 任务、运行时准备期间停止，以及 stop 后重新运行、shutdown 后拒绝执行、dev/前台已同时运行、启动中的 EOF 永不返回及取消后的锁文件回传。

### 3. 新增排除规则阻断同步 — 已修复

原问题：旧 baseline 中被新规则排除的文件，被误判为当前远端返回了违规路径。

修复：历史 baseline 保留路径合法性检查，再过滤当前已排除条目；两端原文件不删除。当前远端清单仍严格校验，`accept-local` 也在写入 baseline 前校验，不能把违规清单保存成历史状态。

回归：`tests/integration/sync-regressions.test.mjs`。覆盖规则变更、未排除文件继续正常同步、两端排除文件保留、非法历史路径和违规远端清单拒绝。

### 4. 目录与文件转换使同步失败 — 已修复

原问题：计划删除子文件后留下空目录，挡住同名文件写入；批量 apply 的准备阶段也无法正确处理类型转换。

修复：两端计划删除先于写入，准备检查不修改文件系统。阻挡目标的目录必须整棵验证为空、没有排除路径或 symlink，才逐层 `rmdir`；不用递归删除。合并后出现“普通文件及其子文件”的不可能目录结构，提前按冲突处理，不先改用户文件。

同时加强本地回传：备份与临时文件准备后再次校验 expected hash，防止这段异步准备期间的新编辑被覆盖或删除；push 删除也检查本地源是否已重新创建。失败不推进 agreed baseline，可在解除故障后重试。

回归：`tests/integration/sync-regressions.test.mjs`。覆盖双向两种转换、嵌套空目录、乱序 worker apply、排除文件/空目录/symlink、普通非空目录、结构冲突、旧 hash/类型、编辑竞态及部分失败恢复。

### 5. 空子目录执行失败并误报缺少 Python — 已修复

原问题：文件清单不传输空目录，映射后的 cwd 不存在，被误报为可执行文件不存在。

修复：启动前验证 cwd 位于工作区内，以目录句柄逐层创建缺失目录，不跟随 symlink 父路径，拒绝普通文件阻挡。前台与 dev 共用此路径；cwd 错误与可执行程序缺失/权限错误分开。

回归：`tests/integration/cwd.test.mjs`。覆盖空嵌套目录的前台和 dev 执行、越界/符号链接/文件 cwd 拒绝，以及真实缺少程序的 127 和权限错误的 126。
