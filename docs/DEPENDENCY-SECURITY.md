# Dependency security and npm maintenance

## Scope and decisions

This change keeps `@onedotmint/reroute` at **0.4.0**, as one CLI + Pi extension package. It does not publish, merge, change credentials/configuration formats, or authorize cloud work. All cloud compatibility evidence in this change is offline contract/type checking, not a paid/live-service qualification.

- **Repository:** `package-lock.json` v3, committed; development and CI use `npm ci --ignore-scripts`. No floating CI dependency resolution for Reroute's own tree.
- **Publication:** no `npm-shrinkwrap.json` and no package lock in the tarball. npm 12 no longer honors shrinkwrap, including in dependency tarballs. Removing it is not a security fix by itself: the manifest must also admit safe production dependencies.
- **Production:** keep all six runtime dependencies. Daytona, E2B and Modal remain installed, not optional, so selecting a supported provider does not fail because its SDK was omitted. No new dependency, lifecycle script, or root override is introduced.
- **Version policy:** Daytona `~0.223.1`, Modal `~0.11.0` and E2B `~2.60.0` admit patch releases, not unreviewed SDK minor changes. The small stable libraries use `^` within their current major. Development tools/host SDKs remain pinned in the manifest and lock.
- **Pi:** both directly imported SDKs (`pi-coding-agent`, `pi-ai`) are explicit development dependencies and optional `*` peers. The native TypeScript/jiti loader maps them to the **host's** modules. The compiled CLI entry never needs these peers. A plain consumer install must not pull Pi, GenAI, esbuild or TypeScript. The real independently installed host test proves this mapping without a repository/global module fallback.

An upstream release does **not** upgrade an existing installation. Dependabot changes the repository manifest/lock in a PR; CI uses that exact lock. Consumers obtain allowed versions through their ordinary install/update workflows and may have their own lock. Existing installations need an update/reinstall after a future Reroute release; this PR cannot repair already-published 0.4.0 tarballs.

Full-tree high findings are explicitly printed and retained rather than silently ignored. Normal `npm audit --omit=dev` still exits nonzero for the remaining moderates; CI uses the documented `--audit-level=high` release threshold.

## Installation scripts and least privilege

| Package | Why present | Script / policy |
|---|---|---|
| `@google/genai` | Pi AI development/host tree only | Published `preinstall` prints a no-op. No runtime permission needed; absent from clean Reroute production install. |
| `esbuild` | Pi/Chord development tree only | `postinstall` locates/verifies a platform binary and may download a fallback. Reroute is built with TypeScript and does not need this script. Absent from production. Do not omit platform optional packages and assume esbuild still works. |
| `cbor-extract` | Modal → cbor-x optional native acceleration | Install probes/builds a native helper. Not needed for correct CBOR operation; cbor-x has a JS fallback. Clean installation tests explicitly exercise that fallback with `CBOR_NATIVE_ACCELERATION_DISABLED=true`. Skipping acceleration may affect performance, not protocol correctness. |
| `protobufjs` | Modal and gRPC runtime | Published postinstall emits dependency-version advice; no compilation/download is required. Installed protobuf encode/decode is tested with all install scripts disabled. |

No consumer script approval is required for Reroute's tested CLI/extension path. The pack check tests **both** unmodified npm default policy and `--ignore-scripts`, without `allowScripts`, global approvals, or `dangerously-allow-all-scripts`. npm 11 behavior depends on its minor version/configuration; npm 12 blocks unapproved dependency scripts by default. Pending-script notices are not automatically approved. Reroute has no install lifecycle hooks. If a user independently needs esbuild or native acceleration for another package, review that package/version and use the package manager's **per-package/project** approval, not a global allow-all. This PR requires no such exception.

## Other projects' npm locks

Reroute's own lock migration is separate from remote project support. `src/prepare.ts` continues recognizing shrinkwrap; `src/snapshot.ts` continues hashing **both** npm locks and runtime declarations. npm ≤11 gives shrinkwrap precedence. npm ≥12 ignores it and can silently use a different package-lock when both exist.

The supervised remote preparation now queries the **actual remote** `npm --version` when shrinkwrap exists, refuses npm ≥12 or an unknown/failed version, and does not run either `npm ci` or the main task after refusal. The guard is inside existing timeout/cancellation/process supervision. It never changes project locks, installs another npm, falls back to mutable `npm install`, or retries locally. Use a reviewed npm 11 image or let the project maintainer migrate the lock deliberately. Static environment hints describe this version distinction without claiming `packageManager` selects the actual remote runtime.

References: [npm 12 release](https://github.com/npm/cli/releases/tag/v12.0.0), [npm 11 shrinkwrap rules](https://docs.npmjs.com/cli/v11/configuring-npm/npm-shrinkwrap-json), [npm 12 ci](https://docs.npmjs.com/cli/v12/commands/npm-ci), [npm script policy](https://docs.npmjs.com/cli/v12/using-npm/config/), [Pi package/host dependency contract](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/packages.md).

## Automatic updates and release gate

`.github/dependabot.yml` checks npm and Actions weekly. Only ordinary patch/minor utility/development updates are grouped; Daytona, E2B, Modal and Pi SDKs stay separate, as do majors and security fixes. No major is ignored. Security PRs are GitHub-alert-driven rather than waiting for the version-update schedule. Repository Dependabot alerts and automated security fixes were enabled and confirmed through the GitHub API; auto-merge remains disabled. The new weekly configuration becomes active once this PR is merged into the default branch.

Every PR must pass review and CI. No workflow merges PRs, creates Releases or publishes npm. CI covers Node 22/24 × npm 11.21.1/12.2.1 on Linux (npm 12 itself requires Node ≥22.22.2 or ≥24.15.0 in these lines), preserving SSH, Pi, panel/PTYS, AFT coexistence, safety/budget tests and benchmarking. A separate Windows job builds and checks lock discovery, routing and the CLI entry; it is **not** a claim that Linux execution targets or native Unix commands work on Windows.

`check:package` packs the actual commit, checks the allowlisted files, installs in fresh consumer roots (no starting lock), checks production high/critical audit independently, then runs CLI setup/doctor/explain/local and real Pi registration in a separately installed host. It verifies there is no Pi SDK/GenAI/esbuild/TypeScript in the consumer tree, exercises production SDK imports and CBOR/protobuf, and records actual installed package counts, disk use, runtimes, tarball integrity, source commit and dirty-state in `.artifacts/package-verification.json`. The install/probes use temporary HOME/XDG/Pi directories and empty npm configs, never personal keys or global installations.
